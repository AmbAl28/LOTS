# Кривое зеркало v2 — WebGL + распознавание лиц

Эволюция папки «Кривое зеркало» из репозитория LOTS. Тот же принцип («источник → канвас с
эффектами → просмотр/запись»), но: эффекты перенесены на GPU, а к ним добавлен
реалтайм-контур распознавания и трекинга лиц с маской.

## Что изменилось против v1

| | v1 (`Кривое зеркало/app.js`) | v2 (эта папка) |
|---|---|---|
| Исполнение эффектов | попиксельный JS по `ImageData` (2 вложенных цикла на кадр) | один проход фрагментного шейдера WebGL2 |
| Интерполяция | `Math.round` (лесенки/алиасинг) | билинейная выборка текстуры (LINEAR) |
| Производительность 1080p | ~5–15 fps, греется, GC на `new Uint8ClampedArray` каждый кадр | 30–60 fps на интегрированном GPU |
| Источник | только `getDisplayMedia` | файл / URL (CORS) / экран / **веб-камера** |
| Лица | нет | MediaPipe FaceLandmarker, 478 точек, трекинг + EMA-сглаживание |
| Маски | нет | маска лица → GL-текстура; эффект **только на лице** / **кроме лица**; настраиваемый запас и мягкость края |
| Экспорт | нет | запись обработанного `.webm` (MediaRecorder) + PNG-кадр |
| Баги v1 | `video.onended` вместо `track.ended`; отсутствие слушателя `change` у `effectSelect`; размер канваса фиксируется один раз в `onplay` | исправлено |

## Структура

```
mirror-v2/
├── index.html   # UI
├── app.js       # связка: источники, цикл, запись
├── gl.js        # WebGL2-рендерер + шейдер всех эффектов
├── faces.js     # FaceTracker: детекция, трекинг, построение маски
└── vendor/      # офлайн-бандл @mediapipe/tasks-vision (1.0.1) + wasm + face_landmarker.task
    ├── vision_bundle.mjs
    ├── wasm/vision_wasm_*.js|wasm
    └── face_landmarker.task
```

Всё работает без интернета (vendor подключён локально) и без сборки — это статические файлы.

## Запуск

```bash
cd mirror-v2
python3 -m http.server 8000     # или: npx serve .
# открыть http://localhost:8000
```

HTTPS (или localhost) обязателен только для getDisplayMedia/getUserMedia.

## Как пользоваться

1. **Источник**: «📁 Файл» (надёжнее всего), «🎥 Камера» (погонять маски на себе), «🖥 Экран»
   (вкладка с YouTube — кроме DRM-плееров) или «🔗 URL» (прямой .mp4/.webm с CORS).
2. **🧠 лица** — включает MediaPipe FaceLandmarker (первый клик = загрузка модели ~3.7 МБ).
3. Режим маски: *эффект везде* / *только на лице* / *кроме лица*. Ползунки «Маска: запас /
   мягкость» настраивают размер и feather контура.
4. **⏺ Запись webm** — сохраняет ровно то, что видите вы (эффекты + маска), со звуком
   источника, если это был захват экрана с аудио.

## Как это устроено (кратко)

- Кадр видео грузится в GL-текстуру (`texImage2D`), шейдер делает *обратное отображение*
  (для каждого выходного пикселя считает UV источника) — так же, как в v1, но на GPU.
- Маска лица: 478 лендмарок → выпуклая оболочка → раздувание от центра на «запас» →
  заливка с блюром на low-res канвас (¼ кадра) → вторая GL-текстура.
- Трекинг: nearest-neighbor сопоставление центров + EMA(0.45) по точкам; id лица стабильны,
  при пропаже на >4 кадров трек удаляется.
- Детекция идёт каждый 2-й кадр на 480px — остальное сглаживается; на CPU-делегате
  это ~10–20 МС, на GPU — ~5 МС.

## Дорожная карта (следующие шаги)

1. Маска по триангуляции (FaceGeometry) вместо выпуклой оболочки → точные «обрезанные» маски.
2. Blendshapes (`outputFaceBlendshapes: true`) → маски, реагирующие на улыбку/моргание.
3. Накладывание картинок/3D-масок на лицо: аффинное выравнивание по глазам/рту +
   perspective-warp в том же шейдере.
4. Face-swap в браузере: ONNX-модели (SimSwap/inswapper) через `onnxruntime-web` + WASM —
   реалистично на 1080p ≈ 1–3 fps; для качества — серверная обработка (см. README v1-репо → «Идеи»).
5. WebGL-шейдерный композитинг оверлеев (маска-«стикер» из PNG поверх лица).

## Ограничения

- `getDisplayedTab`-захват не работает внутри sandboxed iframe без `allow=*` и на страницах
  без HTTPS (кроме localhost).
- DRM-контент (Widevine) при захвате даёт чёрный экран — это ограничение браузера, обходится
  только серверным рендером исходников, которых у вас нет на руках легально.
- Кросс-доменный URL без CORS «отравляет» канвас: показать-то покажем, но читать пиксели и
  писать в запись браузер не даст (в v2 это корректно диагностируется и сообщается).
